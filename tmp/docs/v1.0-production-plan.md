### 1.4 The one decision that unblocks everything — #101

- **#98** → narrow `update` to `Partial<Omit<T,'id'>>` stands as-is.

2. **Phase B — Breaking behavior fixes (#96, #97, #98, #83).** These change public types/behavior and **must precede the tag** (changing them post-1.0 is itself a breaking change). #80 merges here (already implemented on branch — verify against criteria).
3. **Phase C — Security (#81, #100).** Independent; can run in parallel with B.
4. **Phase D — CLI/migration correctness (#82, #99, #102).** Independent; parallel with B/C.
5. **Phase E — Build/release guard (#85) + verify #84.** Needed before any publish.
6. **Phase F — Test gaps (#86) + dead-code cleanup (#103).** Do last, once the public surface is final, so tests assert the frozen behavior and removals are safe.
7. **Phase G — Freeze, version bump, release.**

### 2.3 Parallelization

- B, C, D are mutually independent → can be separate PRs in parallel.
- A must merge before the #83/#97/#98 parts of B.
- F must be last (asserts frozen surface).

## 3. Spec (Acceptance Criteria)

> Each issue gets: **Change**, **Acceptance**, **Test**. Breaking items flagged ⚠️.

### WS-A — PK/id contract

**#101 ⚠️ (decision + docs)**
- Change: pick Option 1 or 2; if Option 1, add `validateSchema` rule rejecting `@id` fields not named `id`.
- Acceptance: a schema with `idColumn: 'userId'` (Opt 1) fails validation with an actionable message; contract documented in README/skills.
- Test: validator unit test (reject non-`id` @id), doc snippet compiles.

**#83 ⚠️ (Opt-2) / validate-only (Opt-1)** — `types-generator.ts:45`, `client-package-generator.ts:83-89`
- Opt-1: generator asserts `@id` field is `id`; existing hardcode becomes correct-by-contract.
- Opt-2: look up actual `@id` field name from schema AST; relation aliases + `extends RowWithId` use it.
- Acceptance: generated code compiles for the supported contract; (Opt-2) a custom id name generates valid TS.
- Test: codegen snapshot for a schema; (Opt-2) snapshot with custom id.

**#98** — `mock-adapter.ts:251`
- Change: narrow `update` to `Partial<Omit<T,'id'>>` or strip `id` before applying.
- Acceptance: `mock.update(1,{id:99,...})` rejected/ignored; `findById(1)` still valid, no ghost row; matches SheetsAdapter.
- Test: repro from issue → no idIndex corruption.

**#103 (idColumn item)** — `runtime.ts:45-50`
- Change: `GeneratedSchema.tables` carries `idColumn` (or, under Opt-1, document it's intentionally `id`-only and remove the dead field).
- Acceptance: no silent drop; consistent with #101 decision.

### WS-B — Core data integrity

**#80** — `sheets-adapter.ts:262-275, 440-452` *(implemented on branch)*
- Change: hold LockService lock across compute-ID → write → release; `batchInsert` reads `getLastRow()` inside lock.
- Acceptance: no duplicate IDs under concurrent inserts; lock released in `finally`.
- Test: existing branch tests (62 new lines) cover this — **verify they assert atomicity/lock ordering**, not just happy path.

**#96 ⚠️** — `query-builder.ts:168, 311, 324-325`
- Change: snapshot/restore `limitValue` (or use scratch builder) in `first()`, `exists()`, `JoinQueryBuilder.first()`.
- Acceptance: issue repro — `qb.exec()` after `qb.first()` returns full result set again.
- Test: reused-builder test for all three methods.

**#97 ⚠️** — `type-mapping.ts:18-19`, `sheets-adapter.ts:142-145`
- Change (assumed generator-side): generator emits `columnTypes: { <field>: 'date' }` into SheetsAdapter config so `deserializeByType` runs and `datetime` returns real `Date`.
- Acceptance: `row.createdAt.getFullYear()` works on the generated client against the Sheets path; type matches runtime.
- Test: adapter test with a `datetime` column round-trips to `Date`; generator emits `columnTypes`. (Note: MockAdapter tests won't catch — add a Sheets-path test.)

### WS-C — Security

**#81** — `viz-query.ts:157-162, 108-114`
- Change: escape regex metacharacters (keep intended `%`/`_`), route literal through `toQueryLiteral`, anchor `^...$`, backtick-wrap field names in `toColumnRef`.
- Acceptance: `whereLike('name', "O'Brien")` and `"' or 1=1 or '"` produce a safe, correctly-matching query; no clause injection.
- Test: query-string assertions for quotes, metacharacters, field names.

**#100** — `migration-create.ts:134-136`
- Change: reject `/`, `.`, `\` in name (or `path.basename` + assert resolved path stays under migrations dir).
- Acceptance: `migration:create '../../../evil'` is rejected; normal names unaffected.
- Test: traversal input rejected; normal name writes inside dir.

### WS-D — CLI / migration correctness

**#82** — `migration-utils.ts:54`

**#99** — `migration.ts:316` (and guard `:302`)

- Acceptance: issue repro — rollback `addColumn` default IS applied after a prior `removeColumn`.
- Test: up(removeColumn)/down(addColumn default) round-trip applies default.

**#102** — `sanitize.ts:17-30`
- Change: add `null`, `undefined`, `true`, `false` to `RESERVED_WORDS`.
- Acceptance: a table named `null` generates a sanitized, valid identifier.
- Test: sanitize unit test for the four literals.

### WS-E — Build / release / DX
